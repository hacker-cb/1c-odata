MCP `query` and `register_query` now mark a page they cannot place with an optional `pagination.ambiguous` — before, only the summary text said so, and in `structuredContent` such a page read as an ordinary last one (the requested `skip`, rows that may be the table's first, `hasMore: false`), so a client reading only the structured result could join duplicates to the pages before it. `"skipIgnoredOrCountShort"`: at a `skip`, 1С sent as many rows as it counted (or, ignoring `$top`, more) — it either ignored `$skip` or counts fewer rows than it has (a `select` on a register virtual table, counted rolled up). `"skipUnverified"` (`query` only): at a `skip`, 1С ignored `$top` and no count was asked for, so whether it kept to `$skip` is unknown. A first page (no `skip`) where 1С ignored `$top` without a count is no longer taken for such a page: no `$skip` was sent, so its rows start at the first, and it now answers `hasMore: true` (rows past `top` came back) where it answered `false`. The field is present only on such a page, which ends the paging (`hasMore: false`); every other response is unchanged. The tool descriptions and a new README section on paging describe it.
