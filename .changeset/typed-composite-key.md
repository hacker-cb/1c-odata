A composite entity key takes typed values: `EntityKey` is now `string | Record<string, string | number | bigint | boolean | Date>`, and each value is written by its JS type, as the 1С docs show it — a `number` or `bigint` bare (`LineNumber=1`), a `boolean` as `true` / `false` (registers key on `Edm.Boolean` fields too), a `Date` as `datetime'…'` in the connection's `serverTimezone` (`Period=datetime'2025-01-01T00:00:00'`), a string as before (a GUID → `guid'…'`, anything else a quoted literal, which 1С converts to the field's type). A row read back keys itself: `client.entity('InformationRegister_КурсыВалют', { Period: row.Period, Валюта_Key: row.Валюта_Key })` — a `Date` key used to be an `InvalidArgumentError`. A `number` value, which untyped callers could already pass, now goes out bare (`LineNumber=1`) instead of quoted (`LineNumber='1'`); 1С accepts both. An invalid `Date`, a non-finite number, or a value of another type is an `InvalidArgumentError`; a `Date` from another realm (`node:vm`) is accepted; within one call a `Date` value is copied, so a caller reusing it cannot split an `expectVersion` check and its mutation across two rows. Values that do not key their row as read: the empty date (read as `null` — pass `ONEC_EMPTY_DATE`), an `Edm.Int64` past 2^53 under the default `int64Mode: 'number'`, a time a daylight-saving switch skips, and a string the schema-less date heuristic took for a date-time. Migration: code that reads the values of an `EntityKey` object now sees the wider union — narrow with `typeof` / `instanceof Date` before using a value as a string.
