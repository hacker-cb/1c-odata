`1c-odata-mcp serve` now exits once the MCP client closes its end of stdin (EOF, or the stream closing) — the shutdown signal of the MCP stdio transport — and on an error on stdin or stdout (the client gone mid-write). Before, the server never noticed: a call the client had abandoned kept its requests to 1С open until 1С answered, and the process stayed up meanwhile. Now the server closes, which aborts every tool call still running together with its requests to 1С (as a cancel does) and its `$metadata` downloads in flight — those no single call's cancel aborts, being shared by every call waiting on the connection. A call still running when stdin ends gets no answer: a client that wants one waits for it before closing stdin. `runServe()` now resolves when the server closes, as its documentation said, instead of right after it starts. A server from `createMcpServer()` closes its connection pool with itself, over any transport. `ConnectionPool` (from `@1c-odata/mcp/internal`) gains `close()`, which aborts its `$metadata` downloads in flight and fails every later one at once, for a host shutting the pool down with its server; entries already built stay usable.
