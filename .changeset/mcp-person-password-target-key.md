**Breaking (storage format).** A password of a connection a person added is now stored under a key bound to its server — `<name>+<16 hex of sha256(base URL)>` in the OS keychain and in `credentials.json` — as an agent's connection already was (`<name>@<…>`). Before, it was stored under the bare `<name>`: a copy a locked keychain kept after `remove`, or one an `--insecure-storage` process (or one without the keychain backend) could not delete on a re-point, was read again for the same name — and sent to the new server a person re-pointed the connection to with `add --force` and no password. A password is now only ever read for the server it was stored for. Such a connection is marked `"passwordKey": "target"` in `config.json`.

Migration — nothing to do: a connection added before keeps its password under `<name>` and is read there, until it is next changed. An overwrite on the same base URL (`add --force`, `add_connection` with `overwrite`, e.g. a new label or timezone) or `set-credentials` / `set_credentials` moves the password to the server's key; a re-point to another base URL without a password leaves the new key empty, as before. `label` / `set_label` change only `config.json` and leave the password where it is.

- **Downgrading to 0.12 or earlier** finds no password written by this version (it reads `<name>` only): enter those passwords again (`1c-odata-mcp set-credentials <name>`) or use `ONEC_<NAME>_PASSWORD`. A server of an older version still running strips the `passwordKey` mark when it saves `config.json`; restart every MCP client after upgrading.
- **A base URL is compared and keyed as a target in one canonical form**: scheme and host lower-cased, a default port (`:80` for http, `:443` for https) dropped, the path kept as written. `https://host:443/…` and `https://host/…` are now the same server — an agent may overwrite its connection naming either, and a person's overwrite between them keeps the password. A connection an agent added on a URL written with its default port or an upper-case host finds no stored password after the upgrade: set it again with `set_credentials`.
- `@1c-odata/mcp/internal`: `SecretStore.read`, `source`, `write` and `remove` take the stored connection as a required argument (`read`/`source` accept `undefined` — no such connection — and answer none); `remove` lost its `strict` option.
