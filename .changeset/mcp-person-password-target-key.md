**Breaking (storage format).** A password of a connection a person added is now stored under a key bound to its server — `<name>+<16 hex of sha256(base URL)>` in the OS keychain and in `credentials.json` — as an agent's connection already was (`<name>@<…>`). Before, it was stored under the bare `<name>`: a copy a locked keychain kept after `remove`, or one an `--insecure-storage` process (or one without the keychain backend) could not delete on a re-point, was read again for the same name — and sent to the new server a person re-pointed the connection to with `add --force` and no password. A password is now only ever read for the server it was stored for. Such a connection is marked `"passwordKey": "target"` in `config.json`.

Migration — nothing to do: a connection added before keeps its password under `<name>` and is read there, until it is next changed. An overwrite on the same server (`add --force`, `add_connection` with `overwrite`, e.g. a new label or timezone) or `set-credentials` / `set_credentials` moves the password to the server's key, in the backend it is in (a `credentials.json` copy stays in the file); where it cannot be read there — `--insecure-storage`, a keychain refusing to read — the connection stays keyed `<name>` and keeps it. A re-point to another server, or to another login on the same server, without a password leaves the connection without one, as before: the old password is deleted once `config.json` is saved, and where a locked keychain refuses that, the change is undone and refused. `label` / `set_label` change only `config.json` and leave the password where it is.

- **Downgrading to 0.12 or earlier**: it reads a person's password under `<name>` only, so it finds none written by this version for a person's connection — enter those again (`1c-odata-mcp set-credentials <name>`) or set `ONEC_<NAME>_PASSWORD`. An agent's connection keeps working where its base URL's key did not change (see below). A server of an older version still running strips the `passwordKey` mark when it saves `config.json`; restart every MCP client after upgrading.
- **A base URL is compared and keyed as a target in one canonical form**: scheme and the host's ASCII letters lower-cased, the port read as a number and a default one (`:80` for http, `:443` for https) dropped, the path kept as written. `https://host:443/…` and `https://host/…` are now the same server — an agent may overwrite its connection naming either, and a person's overwrite between them keeps the password. A connection an agent added on a URL written with its default port or an upper-case host finds no stored password after the upgrade: set it again with `set_credentials`.
- `@1c-odata/mcp/internal`: `SecretStore.read`, `source`, `write` and `remove` take the stored connection as a required argument (`read`/`source` accept `undefined` — no such connection — and answer none); `remove`'s options moved to the third argument: `remove(name, conn, { strict })`.
