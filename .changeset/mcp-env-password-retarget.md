**Security:** a password supplied through `ONEC_<NAME>_PASSWORD` can no longer be sent to a server other than the one the connection was set up for. The env password outranks a stored one on read, and an overwrite that changed a connection's base URL or login cleared only the stored one: MCP `add_connection` with `overwrite: true` and another `baseUrl` — a call an agent makes, choosing the URL — pointed the connection at that server, and the next read sent the env password there. Now, while `ONEC_<NAME>_PASSWORD` is set, `add_connection` with `overwrite` and the CLI `add --force` refuse to change the connection's base URL or login (an overwrite keeping both — a label, a timezone — still goes through), and `set_credentials` / `set-credentials` refuse to change its credentials, which reads would not use (they reported `verified: true` for a pair the reads never sent). Each refusal is an `InvalidArgumentError` naming the variable, raised before any request — the env password reaches no new target, not even to verify. Migration: unset the variable before re-pointing or re-crediting such a connection, or add the new target under another name.
