**Security:** a password supplied through `ONEC_<NAME>_PASSWORD` can no longer be sent to a server an agent chose. The env password outranks a stored one on read, and an overwrite that changed a connection's base URL or login cleared only the stored one: MCP `add_connection` with `overwrite: true` and another `baseUrl` pointed the connection at that server, and the next read sent the env password there — as did `remove_connection` followed by `add_connection` under the same name. Now, while `ONEC_<NAME>_PASSWORD` is set: `add_connection` refuses to create a connection under that name (an agent cannot create one; a person adds it through the CLI `add`, which still may), `add_connection` with `overwrite` and the CLI `add --force` refuse to change its base URL or login, and every add refuses to store a password for it — reads would keep the env one (an overwrite keeping the target without a password — a label, a timezone — still goes through), and `set_credentials` / `set-credentials` refuse to change its credentials, which reads would not use (they reported `verified: true` for a pair the reads never sent). Each refusal is an `InvalidArgumentError` naming the variable, raised before any request — the env password reaches no new target, not even to verify. Migration: unset the variable before re-pointing or re-crediting such a connection, or add the new target under another name. An overwrite to the same target written differently (a trailing `/` in a hand-edited `config.json`) no longer clears the stored password, and a connection named after a property every object inherits (`constructor`) is no longer taken for an existing one. Re-pointing a connection without a new password now fails closed: where the OS keychain errors on deleting the old password (rather than finding none), the overwrite is refused and the config keeps the old target — before, the error was ignored, the new URL saved, and the old password, read again once the keychain answered, went to the new server. `--insecure-storage`, which never reads the keychain, stays best-effort there.
